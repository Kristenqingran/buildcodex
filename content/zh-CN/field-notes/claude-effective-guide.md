# Claude 高效使用完整指南

> 原文作者：Anatoli Kopadze；中文完整翻译版。原文来源：[@AnatoliKopadze on X](https://x.com/AnatoliKopadze)。本文中的比例和经验性判断保留原文归属，BuildCodex 未独立验证。

原文认为，大多数人只使用了 Claude 的一小部分能力。它给出的主线不是寻找更多零散技巧，而是先让 Claude 理解你，再把它用作持续的工作伙伴。软件界面可能更新，按钮名称请按含义寻找。

## 从这里开始

### 1. 创建 Project，而不是普通聊天

每次打开新的 Claude 聊天，它都从零开始，不知道你的名字、工作、目标或沟通偏好。Project 是持久工作区，设置一次后，Project 内的对话可以共享相关上下文。

打开 Claude，点击侧边栏的 Projects，创建一个新项目，根据用途命名为“工作”或“个人”，之后把相关内容放在这个 Project 里。

### 2. 告诉 Claude 你是谁

把下面的模板填写后保存到 Project 知识库：

```text
姓名 / 称呼：
职业 / 工作内容：
主要目标（短期 / 长期）：
我喜欢的沟通方式（直接、详细、简洁、有例子等）：
我讨厌的回复风格：
当前正在做的重点项目：
其他重要背景信息：
```

内容越具体，后续回复越容易贴合你的工作方式。

### 3. 把它变成自定义指令

把背景信息提供给 Claude 后，使用下面的提示词：

```text
请根据我提供的个人背景信息，生成一套简洁、明确的自定义指令（Custom Instructions）。
要求：
1. 用第二人称（你）直接对 Claude 说话
2. 包含我是谁、我的工作、我的目标、我喜欢的回复风格
3. 明确告诉 Claude 不要做什么（比如不要废话开头、不要过度总结）
4. 保持简短有力，控制在 300-500 字以内
```

将生成结果复制到 Project Instructions，作为这个 Project 的默认工作方式。

## Claude 不是搜索引擎

### 4. 把问题改成共同思考

不要只问“什么是 prompt caching”，而是交代你的真实场景：

```text
我正在搭建一个工作流，每次会话会调用 Claude 20 次。请一步步告诉我 prompt caching 是怎么工作的，以及在我的场景下它是否真的能降低成本。
```

第二种问法给 Claude 一个需要结合背景解决的问题，而不只是要求背诵定义。

### 5. 先让 Claude 向你提问

复杂任务开始前，先使用：

```text
在你开始之前，请先问我 3-5 个关键问题，确保你完全理解我的需求和背景。问完后等我回答，再开始执行任务。
```

也可以明确指定目标受众、核心信息、语气风格和成功标准。这样可以减少 Claude 基于错误假设开始工作后再返工。

## 即使是普通用户也不知道的技巧

### 6. 风格克隆

提供三到五篇自己写的文字样本，让 Claude 分析句子长度、用词、语气、结构和标点规律，而不是只给出“你的风格是……”的概括：

```text
以下是我写的 3-5 段文字样本。请仔细分析我的写作模式，包括：句子长度、用词习惯、语气、结构偏好、标点使用方式。不要只说“你的风格是……”，而是具体拆解规律。分析完后，用完全相同的风格帮我写……
```

### 7. 把 Claude 当成陪练对手

在决定一个计划、观点或文章之前，让 Claude 进行严格压力测试：

```text
请用最严厉、最不留情面的方式攻击下面这个想法。指出所有漏洞、风险、不合理的假设和可能失败的地方。不要给我鼓励，只给我真实的问题。
```

### 8. 开启深度思考

简单任务不需要深度思考。对于复杂决策和分析，可以在 Claude 中点击大脑图标，或在提示中加入：

```text
请开启深度思考模式，一步步推理后再给出最终答案。
```

### 9. 让 Claude 为自己写提示词

当你不知道如何描述任务时，可以先让 Claude 生成提示词，再执行：

```text
我想让你帮我完成【具体任务】。请先为我写一个高质量的提示词，这个提示词应该能让你发挥出最好水平。写完后直接用这个提示词执行任务。
```

## 如何少花 Token 却得到更多

### 10. 明确指定输出长度

在开始时说明长度和格式，例如：

```text
请用不超过 200 字回答。
用三点总结，每点一句话。
```

原文认为，这通常能在许多任务中减少 40%–60% 的 Token；这个比例是原文经验性判断，不是本文测试结论。

### 11. 去掉废话开头

可以在自定义指令中加入：

```text
直接给出答案，不要开场白、不要复述我的问题、不要免责声明、不要结尾总结。除非我明确要求，否则不要添加额外内容。
```

### 12. 不要在每次对话中重新解释自己

把稳定的背景信息放进 Project 和自定义指令，而不是每次新聊天都重复粘贴。这样可以减少重复输入，让新对话直接继承必要背景。

### 13. 换话题就开新聊天

Claude 会携带当前聊天中的上下文。切换到不相关的事情时，在同一个 Project 中开新聊天，保留 Project 记忆，同时丢掉当前话题的无关内容。

## 现在就能直接用的提示词

### 14. 用类比理解任何事物

```text
请用费曼学习法向我解释【概念】。要求：
1. 用最简单的日常语言，像对一个聪明的中学生解释
2. 至少用一个生动的类比
3. 避免专业术语，如果必须用，先解释它
4. 最后用一句话总结核心洞察
```

### 15. 围绕真实旅行方式规划行程

```text
请根据以下信息为我规划一次旅行：
- 目的地与时间：
- 我的旅行风格（慢节奏 / 高强度 / 美食优先 / 自然优先等）：
- 预算范围：
- 我真正在意的体验（而不是网红打卡）：
- 需要避免的事项：
```

### 16. 分析真实月度支出

```text
以下是我最近一个月的支出明细（或银行流水摘要）。请：
1. 按类别清晰分类并统计金额
2. 指出异常或值得注意的支出模式
3. 给出 2-3 个具体、可执行的调整建议
4. 用一句话总结这个月的财务健康状况
```

### 17. 把 Claude 当成私人思考伙伴

```text
我现在在【具体困境 / 决策】上卡住了。请作为我的思考伙伴：
1. 先问我几个问题，帮我把问题拆清楚
2. 不要急着给建议，先帮我看见自己可能忽略的角度
3. 保持中立，不要站队或推销特定方向
4. 最后帮我整理出我真正在意的优先级
```

这不是心理治疗，而是带有外部视角的结构化自我反思。

### 18. 在投入之前压力测试商业点子

```text
请对以下商业点子进行严格压力测试：
【描述你的点子】
请从以下角度攻击它：
1. 目标用户真的有这个痛点吗？强度如何？
2. 现有解决方案为什么不够好？
3. 最大的执行风险和假设漏洞是什么？
4. 如果一年后失败了，最可能的原因是什么？
不要给我鼓励，只给真实的问题。
```

## 真正的重点

原文最后的观点是：Claude 的价值不只是回答问题，而是它拥有耐心、知识和从不同角度思考的能力。要获得更多帮助，关键是让它理解你的真实上下文，把它当作伙伴而不是答案机器。

设置一次，改变你的工作方式。
